# Repository Hygiene

Abridged English reference for repository cleanup and Git hygiene.

---

## Core Principle

Always distinguish between:
1. Permanent project code
2. Useful documentation
3. Tests
4. Configuration that belongs in Git
5. Generated files that should not be committed
6. Local/development-only files
7. Temporary experiments
8. Debugging artifacts
9. Secrets and credentials
10. Dead or obsolete code

Goal: Leave the repository in a state where another competent developer can clone it and immediately understand the project structure, installation, configuration, testing, and which files are authoritative vs generated.

---

## Key Rules Summary

### Before Git Operations
- Inspect repository root, directory tree, `git status`, current branch, recent commits, changed files, `.gitignore`, project manifest, build system, test system, documentation, CI/CD config, environment files, obvious temporary files, generated files, suspicious filenames, untracked files

### Temporary Patch Rule
- Never blindly keep files like `fix.py`, `fix1.py`, `patch.py`, `debug_fix.py`, `working_version.py`, etc.
- For every suspicious file: determine what problem it solves, whether behavior is already implemented, compare to canonical implementation, check which parts work, check for improvements/bug fixes, search for references, integrate valid fixes, update tests, remove temporary implementation

### Debug Code
- Search for: `print()`, `console.log()`, `debugger`, `pdb`, `breakpoint()`, traceback dumps, temporary logging, verbose diagnostics, development-only endpoints, temporary flags, hardcoded test values, manual bypasses, disabled validation, commented-out code, TODO/FIXME hacks
- Determine if each is: legitimate production logging, test logging, development-only debugging, or accidental leftover
- Remove accidental debug noise

### Log Files
- Never commit runtime logs unless project explicitly requires versioned example logs
- Clean: `*.log`, `logs/`, `debug.log`, `error.log`, `trace.log`, `server.log`, `output.log`, `runtime.log`, `application.log`, `nohup.out`
- Never commit logs containing tokens, API keys, cookies, auth headers, private IPs, credentials, personal data, sensitive filesystem paths

### Generated Files
- Do not commit files generated by build/test/runtime tools unless intentionally versioned
- Check for: compiled binaries, build output, package caches, dependency directories, Python caches, notebook checkpoints, test reports, coverage reports, IDE metadata, OS metadata, temporary archives, generated API clients, generated documentation, compiled frontend bundles, local databases, local model files, downloaded AI models, embeddings, vector databases, runtime state, Docker volumes, application caches

### AI/ML Project Cleanup
- Do not commit: model weights, `.safetensors`, `.gguf`, `.bin` model files, downloaded checkpoints, Hugging Face caches, model caches, embeddings, vector databases, local inference caches, generated images/videos, generated datasets, huge evaluation dumps, temporary inference outputs, local LM Studio/Ollama state, local model metadata, runtime GPU/benchmark dumps
- Watch for accidentally committed: model download URLs with credentials, Hugging Face tokens, OpenAI keys, Anthropic keys, provider keys, private API endpoints, internal inference server addresses, LAN/Tailscale IPs, internal hostnames, local filesystem paths, machine-specific GPU settings, personally identifying metadata

### Secret Protection
- Never commit secrets
- Search for: API keys, access tokens, refresh tokens, passwords, private keys, SSH keys, certificates, JWT secrets, database credentials, cloud credentials, webhook secrets, OAuth secrets, GitHub/GitLab tokens, Hugging Face tokens, OpenAI keys, Anthropic keys, authentication cookies, session credentials
- Inspect: `.env`, `.env.*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `credentials.*`, `secrets.*`, `secret.*`, `auth.*`, `token.*`
- If found: remove from working tree, replace with config variable, add to `.gitignore`, create sanitized example, update documentation, warn user about rotation if already pushed

### Configuration Hygiene
- Separate into: committed (safe portable defaults like `config.example.yaml`, `.env.example`), local (machine-specific/secrets like `.env`, `config.local.yaml`), generated (auto-created, excluded from Git)
- Abstract machine-specific values: `C:\Users\...`, `/home/...`, `127.0.0.1`, `192.168.x.x`, `10.x.x.x`, hostnames, GPU paths, private server addresses, local model directories, local database locations

### .gitignore Maintenance
- Improve `.gitignore` so junk doesn't return
- Check for proper rules: secrets, local config, logs, caches, build output, IDE files, OS files, generated artifacts, AI model data, temporary files, test output, local databases
- Keep understandable, avoid enormous meaningless lists, use comments

### Documentation Hygiene
- Do NOT automatically delete `.md` files — classify them
- Keep: README, architecture docs, setup instructions, API docs, changelog, contribution guidelines, design decisions, troubleshooting, specs, reproducible research, useful technical docs, agent instructions, intentionally maintained docs
- Question: `debug.md`, `notes.md`, `todo.md`, `test.md`, `temporary.md`, `scratch.md`, `analysis.md`, `prompt.md`, `fix.md`, `old_readme.md`
- Integrate valuable info into correct documentation, keep one authoritative source

### Dead Code & Duplicates
- Look for: unused imports/functions/variables/classes, unreachable branches, abandoned modules, obsolete scripts, old feature flags, deprecated config, dead CLI commands, unused dependencies
- Remove when strong evidence of obsolescence
- Prefer single canonical implementation

### Dependency Hygiene
- Inspect for: unused dependencies, duplicate libraries, dev deps in production, local file dependencies, unreproducible dependencies, versions added for temporary debugging, package manager artifacts, vendored packages that shouldn't be present

### Test Hygiene
- Retain real automated tests
- Distinguish from: temporary manual test scripts, debugging scripts, one-off reproduction scripts, benchmark scripts, destructive test utilities
- When integrating a patch, add/update proper test for the behavior

### Git Hygiene
- Before commit: `git status`, `git diff`, `git diff --cached` — know exactly what will be committed
- Every staged file must have a reason to exist
- Review complete diff for: accidental deletions/additions, debug code, commented-out code, secrets, credentials, local paths, noisy formatting, unrelated modifications, temporary patches, generated files, duplicated logic, suspicious config, line-ending conversions, accidental binary files
- Commits should be meaningful and coherent — avoid messages like "fix", "changes", "update", "stuff", "test", "final", "final2", "again"

### Before Push
- "Would I regret this being public?" review
- Check: credentials, API keys, tokens, private endpoints, internal IPs, personal paths, local usernames, logs, screenshots, generated outputs, model files, databases, temporary patches, debug files, personal notes, private documentation
- "If somebody clones this one year from now, will this file still make sense?"
